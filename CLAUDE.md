# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Intrafeur": a Chrome + Firefox (Manifest V3) extension that augments the Epitech pedagogy intranet (`my.epitech.eu`, a React + Mantine + Mantine React Table SPA), plus a small backend it talks to. Two independent apps in one repo:

- `extension/` — TypeScript, bundled with esbuild. No test suite, no linter; `typecheck` is the only check.
- `backend/` — Express + better-sqlite3, shared by all staff; stores factions and student→faction assignments. Deployed via the root `docker-compose.yml` (Dokploy builds `./backend`; token/port come from root `.env`, see `.env.example`).

## Commands

Extension (run from `extension/`):
- `npm run typecheck` — `tsc --noEmit` (this is the verification step; there are no tests)
- `./build.sh` — full build + packaging. Produces `dist/chrome/`, `dist/firefox/`, `dist/intrafeur-chrome.zip`, `dist/intrafeur-firefox.xpi`. (`node build.js` alone builds the two dirs and an intermediate `.xpi`; `build.sh` adds the chrome zip and renames the xpi. There is no `zip` CLI on the dev machine, so packaging uses Python's `zipfile`.)
- `npm run watch` + `npm run dev:firefox` / `npm run dev:chrome` — rebuild on save and auto-reload the extension via `web-ext run` (persistent profile in `extension/.dev-profile/`, so the intranet SSO login sticks). The intranet tab still needs F5 after a reload.
- Version lives only in `package.json`; `build.js` writes it into both output manifests.
- `npm run release:firefox` (`scripts/release-firefox.sh`, settings read from the repo-root `.env`, see `.env.example`) — Firefox self-hosted updates: builds with `FIREFOX_UPDATE_URL` baked into `gecko.update_url` (must be there before signing), signs unlisted on AMO via `web-ext sign`, then PUTs the signed xpi to the backend's `/extension/releases/<version>` (`RELEASE_TOKEN`, separate from `ALLOWED_TOKENS`). The backend stores releases in `DATA_DIR/releases` and serves the public `/extension/updates.json` (links built from `PUBLIC_URL`) and `/extension/latest` (302 to the newest `intrafeur-<version>.xpi`, a stable install link). Chrome gets no `update_url`; it updates through the Web Store (unlisted).
- `optional_host_permissions: <all_urls>` is used: it's what `options.ts` requests for the user-configured backend origin. Don't remove it.
- Load `dist/chrome` unpacked in `chrome://extensions`. **After every rebuild the extension must be reloaded there AND the intranet tab must be genuinely reloaded (F5)** — content scripts are not re-injected into already-open tabs, and in-app SPA route changes are not reloads.

Backend (from `backend/`): `npm run build` (tsc), `npm start`, `npm run typecheck`. Locally it only really runs in Docker (`docker compose up --build` from the repo root) — `better-sqlite3` fails to compile on the host Node version; use `npm install --ignore-scripts` if you only need typechecking.

## Architecture

**Extension entry points** (each is one esbuild IIFE bundle): `background.ts`, `options/options.ts`, `popup/popup.ts`, `setup/setup.ts` (quick setup wizard, opened by `runtime.onInstalled` on first install), and **two content-script bundles, one per world**: `content/isolated.ts` (imports `init` from `shared/mirror.ts`, `attendance.ts`, `unit-filters.ts`, `eval-sheet.ts`, `intrastek.ts`, `hide-grades.ts`, `planning-board/board.ts`; `webextension-polyfill` inlined once) and `content/main-world.ts` (`"world": "MAIN"`, Chrome 111+ / Firefox 128+; imports `init` from `eval-sheet-page.ts`, `intrastek-page.ts`, `absence-status.ts`, `student-units.ts`, `attendance-present.ts`, `planning-feed.ts`, `promotion-tags.ts` — they read React fiber data, which isolated-world scripts can't see, so they can't use `browser.*` or import the polyfill). Feature modules have **no top-level side effects**: they export `init()`, called once by the entry inside a try/catch (one feature failing doesn't stop the others). Two manifests (`manifest.chrome.json` service worker vs `manifest.firefox.json` background scripts + gecko settings) — keep them in sync; both content-script entries are on the broad `https://my.epitech.eu/*` match and features self-gate at runtime.

**Shared foundation** (use it, don't re-implement): `settings.ts` `FLAGS` = registry of every per-browser feature toggle (storage.local key, default, optional `mirror` dataset key for MAIN-world features; `mirroredFlagOn`); `content/shared/mirror.ts` mirrors those onto `<html data-…="on">`; `content/shared/dom-watch.ts` `watchDom(check, opts)` = the **single throttled MutationObserver per bundle** every feature subscribes to (instead of one observer each); `content/shared/ext-storage.ts` (`getLocal`/`onLocalChange`/`watchFlag`, swallow "Extension context invalidated"); `content/shared/mantine.ts` (MAIN-world Mantine/dialog helpers: `dialogs`, `dialogEvent`, `findUnitLink`, `cloneButton`, `setButtonLabel`); `content/shared/ui.ts` (`el`, `button`, `armable` two-click confirm, `captureEscape`, `toast` (`.epitools-toast`), `spinner`, `setBusy`) styled by `content/shared.css`.

**i18n** (`src/i18n/`, see its README): English + French. `defineMessages(en, fr)` per feature dictionary (`src/i18n/<feature>.ts`; `fr` must have the same keys, typechecked) → `t(key, {vars})`. Preference `language` (`auto`|`en`|`fr`) in storage.local; `initLang()` runs first in the isolated entry, background and pages, and writes the resolved language onto `<html data-epitools-lang>`, which MAIN-world `t()` reads. Already-rendered UI changes language after F5. Manifest strings: `_locales/`. Label lists used to *detect* the site's UI (both site languages) are not translations — never route them through `t()`.

**Extension pages** (`src/ui/` shared by all three, styled by `ui/pages.css`): the popup is a chrome://flags-like searchable list (`ui/features.ts` `FEATURES`, keyed by `FlagId` so every flag needs metadata; select Default/Enabled/Disabled — Default removes the key — plus Language and "Configure →" links that open `options.html#<section>` via `tabs.create`, since `openOptionsPage()` takes no hash). Options = sidebar sub-sections `#general #features #factions #intrastek #about`, each field showing its default with a reset button. `setup/` = 5-step quick setup wizard (language, faction backend URL+token, Intrastek key, features, done). Connection logic (origin → `permissions.request` as the first await → save/test) lives once in `ui/connections.ts`. HTML holds only structure + `data-i18n*` attributes (`applyI18n`).

**Features:**
1. *Factions* (`content/attendance.ts` + `dom-inject.ts` + `fiber-extract.ts`): injects a Faction column/badges into every student table and student card list on the site, with sort/filter and a CSV export that hijacks the native export button. Faction data is shared (backend); the content script never calls the API directly — it messages `background.ts`, which owns fetch/auth (`apiFetch`). Connection settings are in `storage.sync`; the per-browser "factions enabled" toggle is in `storage.local` (popup).
2. *Unit filter presets* (`content/unit-filters.ts`, `unit-filters-dom.ts`, `modal.ts`; off by default, popup toggle `unitFiltersEnabled` in `storage.local` — disabling removes the toolbar but leaves the table's current filter values alone): only on `/units/my`, only the "Current units" table's column-filter row. Purely local (`storage.local`), no backend. Preset selector + Save/Reset buttons injected into that table's toolbar; the built-in "Default" preset is a synthesized constant (never stored) so it can't be overridden.
4. *Evaluation sheet PDF* (off by default; popup toggle `evalSheetEnabled` in `storage.local`): a "Fiche d'évaluation" button in the planning event modal opens an options modal, then downloads a French grading sheet (activity, module, location (`event.rooms`), day, time; per student photo, name/email, one score box per configured notation field — default Participation /5 and Acquisition /5 — and an optional blank Commentaire column; sorted by email). Regular events get one header button; events with `activitySlotsEnabled` get one button per appointment time slot plus a header button "Fiche (tous les créneaux)" for the whole event: students carry `slotStart`/`slotEnd`, are sorted by slot then email, and the PDF adds a narrow leftmost column with the slot time written vertically (`rotate90` text in `pdf.ts`), merged over that slot's rows. In landscape a slot that would be split but fits on one page (≤ 4 students) starts on the next page instead; larger slots (and portrait) split, with the cell re-drawn on each page. Split in two worlds:
   - `eval-sheet-page.ts` (MAIN) injects buttons and reads data from the site's React Query cache (QueryClient found via fibers, `findQueryClient`): `['events','detail',id,'registrations']` and `['eventSlots','list',id]`. Photos: `GET /api/users/<login>/avatar` needs the site's bearer token (cookies get 401), and the site does **not** load student avatars in the event modal, so they're fetched through the site's own generated API client, found as a React context value on a fiber ~20 levels above the dialog (`findApiClient`: `api.unlabeled.getAvatar(login)` → 240×240 JPEG Blob, converted to a data URL in the MAIN world; fallback `getAvatarThumbnail` → 96×96 data URL or null), 6 at a time. Don't read MSAL tokens from localStorage instead. Slot cards are matched to slot groups **by content** (times in the header + student names), never by position, so a sheet can't get the wrong students.
   - It hands the data to `eval-sheet.ts` (isolated) via `window.postMessage` (with a `requestId`, also set as `data-epitools-request-id` on the button; the reply is just an ack `epitools-eval-sheet-ack` within 5 s, after which progress/errors live in the options modal). That script opens the options modal (`eval-sheet-modal.ts`: orientation, comment column, reduced header = module + date/time only, custom notation fields, presets) (the toggle reaches the MAIN world as `<html data-epitools-eval-sheet="on">` via `shared/mirror.ts`), re-encodes the photo data URLs to JPEG via canvas (only `data:image/` URLs are accepted — the postMessage is forgeable), and builds the PDF. (Photos used to be presigned S3 URLs fetched via the background with an optional host permission; that path was removed when the site switched to its own avatar endpoint.)
   - PDF is produced by a tiny hand-written writer (`pdf.ts`; standard Helvetica with WinAnsiEncoding, JPEG images) — not jsPDF (innerHTML/AMO, optional dynamic imports). `pdf-fonts.ts` widths are generated from the metric-compatible URW NimbusSans fonts; don't hand-edit. Layout is in `eval-sheet-pdf.ts`; `maxFields()` there is the single source of truth for how many notation columns fit, used by the modal too. Portrait = separate photo column; landscape = compact 3-column header, photo stacked above name/email in one column, exactly 4 tall rows per page, narrow score columns so the comment column gets the space.
   - Options modal: mounted **inside the intranet's Mantine dialog** (found from the button's request id), not under `<body>` — Mantine's focus trap and react-remove-scroll would otherwise eat focus and wheel events. Escape: Mantine closes the event modal from a window capture keydown listener registered before ours, so stopPropagation is not enough; `captureEscape(onEscape, root)` (shared/ui.ts) marks every element focused inside our popup with `data-mantine-stop-propagation="true"`, Mantine's only opt-out (verified live 2026-11). Own backdrop class (`epitools-es-backdrop`), never `.epitools-modal-backdrop` (`closeSaveFilterModal` removes those). Presets (`eval-sheet-presets.ts`) follow the units model: synthesized "Défaut" (`__default__`, never stored), `evalSheetPresets` + `evalSheetSelectedPresetId` in `storage.local`, sanitized on load; plus delete (two-click confirm, no `confirm()`).

5. *Intrastek* (AER staffing of intranet events in the Intrastek app, `https://intrastek.epistone.fr`; on as soon as an Intrastek key is saved in the options, **no popup toggle** by design, the popup only says so). Files: `content/intrastek-page.ts` (MAIN: tags the event modal), `content/intrastek.ts` (isolated: key gate + the modal's Intrastek button), `content/intrastek-ui.ts` (`mountEventEditor` single-event editor and `mountBulkEditor`, both mounted by the planning board's panel, plus the modal popup that wraps the single editor), `content/intrastek-client.ts` (messaging, status cache, shared `loadMe`/`currentMe`, `runWrite`/`runWrites`, helpers). The planning staffing UI is the planning board's panel (feature 10), `content/intrastek.css`; `intrastekFetch` + `intrastek*` handlers in `background.ts`; Intrastek section of the options page.
   - **Storage (all `storage.local`, never sync: the key is personal):** `intrastekApiUrl` (default `https://api.intrastek.epistone.fr`), `intrastekApiKey` (`ik_…`, teachers and admins only: self-issued on their Intrastek profile page, or issued by an admin; the options page says where), `intrastekDefaultGroupId` (target group of the board's colours/actions and the popup's default; else the user's own group, else the first allowed one; the board panel's group select writes it too), `intrastekModeEnabled` (the board's Intrastek mode: no settings row, only the header button, `INTRASTEK_MODE_KEY` in `board.ts`). Options: Save requests the optional host permission for the API origin (first `await` of the click, like the faction backend) and an empty key removes it (feature off); Test connection requests the permission too, then calls `/extension/me` with the *typed* values (`intrastekMe` accepts an `{apiUrl, apiKey}` override) without saving, showing name, admin/proposer role, scopes, and filling the default-group select (`me.groups`, preselecting the saved id or `me.defaultGroupId`).
   - **Old Intrastek mode (native calendar, only while the new planning calendar `FLAGS.planningBoard` is off)** (`intrastek.ts` + `intrastek-calendar-ui.ts`): a users-icon toggle cloned before the site's planning-mode button (`data-epitools-ik-mode-native`, same `intrastekModeEnabled` key as the board's button) outlines the site's `.scheduler-event` blocks by state for the target group (+ badges), adds a legend under the header (group select, counters, AERs needed); left-click = the event modal + our popup auto-opened in it (Alt+click: modal only), Ctrl/⌘+click = select blocks → bottom selection bar (bulk writes), right-click = menu (init/edit AERs prompt, remove, approve/reject, cancel). `intrastek-page.ts` tags the blocks (`extractSchedulerEvent`, `data-epitools-event-*` incl. `-activity`) only while the board flag isn't mirrored on.
   - **Two worlds, the key never reaches the page:** the isolated `intrastek.ts` mirrors "key present" onto `<html data-epitools-intrastek="on">`. While it's set, `intrastek-page.ts` tags the event modal (`section[role=dialog]`, found via `shared/mantine.ts` `dialogEvent`) with `data-epitools-event-id` (+ `-title`, `-start`, `-end` for display), re-reading the fiber on every check and writing only changed values. The isolated side treats these as untrusted: ids must be positive integers (`parseEventId`), the rest is only rendered via `textContent`; the background re-validates ids before building URLs.
   - **Background:** `intrastekFetch` reads storage.local, checks `permissions.contains` for the API origin, sends `X-Api-Key` (Content-Type only with a body: Fastify rejects an empty JSON body). Handlers `intrastekMe`, `intrastekStatus` (chunks of 200 ids), `intrastekSet`, `intrastekRemove` (`force`), `intrastekApprove`, `intrastekCancel` **never throw**: they resolve `{ok:true,data}` / `{ok:false,status,message}` (an Error crossing `sendMessage` loses its status, and the UI needs 409). Messages: API `message`; 401 → "Invalid or expired Intrastek key", 403 with "disabled" → "Intrastek extension feature is disabled by an admin", 503 → "Intrastek can't reach the intranet".
   - **API contract** (source of truth: the `/extension/*` paths of the Intrastek repo's committed `apps/api/openapi.json`, regenerated by `pnpm api:types` and drift-checked in its CI; the types are mirrored in `src/types.ts`. `X-Api-Key` only, scopes `INTRANET_READ` for me/status and `INTRANET_WRITE` for the rest): `GET /extension/me` → user, `isAdmin`, scopes, `groups` (every visible group, for admins and teachers alike; hidden ones left out), `defaultGroupId` (the user's group when offered, else null: teachers usually have none); `POST /extension/events/status {eventIds}` (1..200) → one `{eventId, activities[], proposals[]}` per id (PENDING proposals only; every key holder sees every group); `PUT /extension/events/:eventId {groupId, nbUserAsk}` and `DELETE /extension/events/:eventId?groupId=&force=` → `{result: 'applied'|'proposed', state}` (admin applies: DRAFT activities, a long event split at the largest pause between its intranet slots / soft delete, 409 when assignations exist without `force` — the extension appends `&force=true` only when forcing, never `force=false`; teacher creates or updates their single PENDING proposal, INIT/UPDATE/REMOVE, on any visible group; a hidden group is a 403 for teachers, an unknown one a 404); `POST /extension/proposals/:id/approve` (admin) and `DELETE /extension/proposals/:id` (author cancels, admin rejects). The server fetches the intranet event itself; nothing the extension sends about the event is trusted, and nothing writes to my.epitech.eu.
   - **Merged events (Intrastek ROADMAP #113):** back-to-back events of one intranet activity (same Paris day, next start ≤ 15 min after the previous end) are **one** Intrastek activity on the first event (the head). `status` of a follower returns the head's activities, each with `headEventId` (≠ the asked id); a write on a follower is a **409** "This event follows event N…". pending proposals made on the head come back on its followers too (proposal `eventId` = the head); `groupView().linkedTo` = the API's `headEventId`, else such a proposal's `eventId`, else a display-only guess from the planning board's events (`setPlanningIndex` → `guessHead`, using each event's `activityInstanceId`), kept only when that guessed first event is itself on Intrastek (activities or a pending proposal in the group, from the status cache). Followers: board cards get a dashed "link" badge (+ the head's count), the bulk editor skips them, the single editor shows a note and no write buttons.
   - **Event modal:** an "Intrastek" button before the × (after "Fiche…" when present) with a state dot over every group the key sees (green initialized, orange pending proposal, grey none, hollow unknown). It opens a popup mounted inside the Mantine dialog (same reasons and Escape capture as the eval-sheet modal; own backdrop `epitools-ik-backdrop`): title/date, group select (default = configured group), state per group (count, AERs needed, status, assigned) and pending proposal (kind, value, author, "yours"), "AERs needed" prefilled from the proposal else the activities. Admin: Apply, Remove (two-click; on 409 a "Remove anyway" with `force=true`), Approve/Reject when pending. Teacher (any non-admin key holder): Propose / Update my proposal, Propose removal, Cancel my proposal; another user's pending proposal is shown read-only and disables proposing for that group. Toast: "Applied" or "Proposal sent – waiting for admin approval".

## Conventions and hard-won gotchas

The intranet's DOM is not under our control, so most non-obvious code exists to survive its quirks. Check these before changing behavior:

- **Detect by DOM shape/content, not header text or URL.** The site is localized (French verified) — column headers, aria-labels and button labels differ. Student tables are found by an email-shaped `<p>` in *any* cell (not the first — some views add a leading checkbox column). Where labels are unavoidable, both languages are listed (`REGISTRATION_DATE_LABELS`, `ATTENDANCE_LABELS`, `EXPORT_BUTTON_LABELS`); the units-page filter aria-labels are English-only and unverified in French. The one deliberate URL gate is `unit-filters.ts` (`/units/my`), checked inside the recurring `check()`, not once at init, because navigation is client-side.
- **Modals/tabs mount and unmount without navigation**, so both content scripts run a body `MutationObserver` with a debounced `check()`. Never re-render already-processed rows/badges on every mutation — that self-triggers an infinite loop that hangs the tab. Only re-render on genuine data change.
- **Debounce with `setTimeout`, never `requestAnimationFrame`** (and poll with `setTimeout`): rAF is throttled to a crawl in unfocused tabs and silently stalled reapply flows for 10+ seconds.
- **Throttle `check()`, never a restart-on-every-mutation debounce**: schedule one `setTimeout` on the first mutation and ignore the next ones until it fires (`if (timer !== undefined) return`). The site rewrites its `<style>` tags every ~100 ms on some views (planning with several semesters selected), so a `clearTimeout` + `setTimeout` debounce never fires there: no tagging, no modal buttons.
- **No `innerHTML` with dynamic content** (AMO addons-linter rejects it); build DOM with `createElement`/`createElementNS`. Don't reuse the `.epitools-menu` class for unrelated popups — `closeAnyOpenMenu()` removes every element with it.
- **Driving the site's own React/Mantine inputs from the content script** (units page): set text via the native `HTMLInputElement.prototype.value` setter + a bubbling `input` event. Mantine comboboxes (Semester/Campus) only open on a *value change* (not focus/click); resolve the listbox via the input's own `aria-controls` (a global `[role=listbox]` query can hit the wrong one); select an option with the full `pointerdown/mousedown/pointerup/mouseup/click` sequence (`.click()` alone does not commit). All of this is flaky on fresh page load, hence: wait for the Name filter input to exist plus a short settle delay before touching anything, retry the open step, and verify-and-retry the whole apply (`applyColumnsReliably`). Compare against current input values first so a no-op apply touches nothing (`''` is a real "clear" target; `null` means "not managed"). Serialize applies through `applyInFlight` so overlapping runs can't fight.
- **Known unfixable site bug:** clicking the native clear (×) on Semester/Campus (by a user or by us) desyncs MRT's internal filter state ("No results found" or the old filter sticking) until a full page reload. The extension shows a warning toast rather than trying to work around it — don't spend time hunting for a workaround; several were tried.
- **Reload/context gotcha:** an "Extension context invalidated" error in a stale tab just means the tab wasn't refreshed after an extension reload; `initFeatureToggle` swallows it.
- **React fibers: read the committed copy.** The `__reactFiber$` expando on a DOM node can be the *alternate* (previous render) fiber, whose props (and its ancestors') lag a render behind; `fiberOf` returns `fiber.alternate` when only that one's `return` chain ends at the HostRoot its FiberRoot calls `current` (verified live: FullCalendar `events` stale after a discard / room change). Always go through `fiberOf`.
- **Debugging content scripts:** isolated-world `console.log` is not visible to the Chrome automation tooling, and the page's `window`/`chrome.*` aren't reachable from injected page JS. Writing diagnostics into a `data-*` attribute on `document.body` (readable from the page world) worked; remove it afterwards. Also don't trust "navigate to the same site" in a reused tab as a reload — open a fresh tab to test a new build.
