# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Intrafeur": a Chrome + Firefox (Manifest V3) extension that augments the Epitech pedagogy intranet (`my.epitech.eu`, a React + Mantine + Mantine React Table SPA), plus a small backend it talks to. Two independent apps in one repo:

- `extension/` — TypeScript, bundled with esbuild. No test suite, no linter; `typecheck` is the only check.
- `backend/` — Express + better-sqlite3, shared by all staff; stores factions and student→faction assignments. Deployed via the root `docker-compose.yml` (Dokploy builds `./backend`; token/port come from root `.env`, see `.env.example`).

## Commands

Extension (run from `extension/`):
- `npm run typecheck` — `tsc --noEmit` (this is the verification step; there are no tests)
- `./build.sh` — full build + packaging. Produces `dist/chrome/`, `dist/firefox/`, `dist/intrafeur-chrome.zip`, `dist/intrafeur-firefox.xpi`. (`node build.js` alone builds the two dirs and an intermediate `.xpi`; `build.sh` adds the chrome zip and renames the xpi. There is no `zip` CLI on the dev machine, so packaging uses Python's `zipfile`.)
- `npm run watch` + `npm run dev:firefox` / `npm run dev:chrome` — rebuild on save and auto-reload the extension via `web-ext run` (persistent profile in `extension/.dev-profile/`, so the intranet SSO login sticks). The intranet tab still needs F5 after a reload.
- Version lives only in `package.json`; `build.js` writes it into both output manifests.
- `npm run release:firefox` (`scripts/release-firefox.sh`, settings read from the repo-root `.env`, see `.env.example`) — Firefox self-hosted updates: builds with `FIREFOX_UPDATE_URL` baked into `gecko.update_url` (must be there before signing), signs unlisted on AMO via `web-ext sign`, then PUTs the signed xpi to the backend's `/extension/releases/<version>` (`RELEASE_TOKEN`, separate from `ALLOWED_TOKENS`). The backend stores releases in `DATA_DIR/releases` and serves the public `/extension/updates.json` (links built from `PUBLIC_URL`). Chrome gets no `update_url`; it updates through the Web Store (unlisted).
- `optional_host_permissions: <all_urls>` is used: it's what `options.ts` requests for the user-configured backend origin. Don't remove it.
- Load `dist/chrome` unpacked in `chrome://extensions`. **After every rebuild the extension must be reloaded there AND the intranet tab must be genuinely reloaded (F5)** — content scripts are not re-injected into already-open tabs, and in-app SPA route changes are not reloads.

Backend (from `backend/`): `npm run build` (tsc), `npm start`, `npm run typecheck`. Locally it only really runs in Docker (`docker compose up --build` from the repo root) — `better-sqlite3` fails to compile on the host Node version; use `npm install --ignore-scripts` if you only need typechecking.

## Architecture

**Extension entry points** (each is one esbuild IIFE bundle; `webextension-polyfill` is inlined): `background.ts`, `content/attendance.ts`, `content/unit-filters.ts`, `content/eval-sheet.ts`, `content/event-info.ts`, `content/event-info-toggle.ts`, `content/eval-sheet-page.ts`, `options/options.ts`, `popup/popup.ts`. Two manifests (`manifest.chrome.json` service worker vs `manifest.firefox.json` background scripts + gecko settings) — keep them in sync. All content scripts are listed on the same broad `https://my.epitech.eu/*` match and self-gate at runtime. `event-info.ts` and `eval-sheet-page.ts` are a separate `content_scripts` entry with `"world": "MAIN"` (Chrome 111+ / Firefox 128+): they must read React fiber data, which isolated-world scripts can't see, so they can't use `browser.*` or import the polyfill.

**Four features:**
1. *Factions* (`content/attendance.ts` + `dom-inject.ts` + `fiber-extract.ts`): injects a Faction column/badges into every student table and student card list on the site, with sort/filter and a CSV export that hijacks the native export button. Faction data is shared (backend); the content script never calls the API directly — it messages `background.ts`, which owns fetch/auth (`apiFetch`). Connection settings are in `storage.sync`; the per-browser "factions enabled" toggle is in `storage.local` (popup).
2. *Unit filter presets* (`content/unit-filters.ts`, `unit-filters-dom.ts`, `modal.ts`; on by default, popup toggle `unitFiltersEnabled` in `storage.local` — disabling removes the toolbar but leaves the table's current filter values alone): only on `/units/my`, only the "Current units" table's column-filter row. Purely local (`storage.local`), no backend. Preset selector + Save/Reset buttons injected into that table's toolbar; the built-in "Default" preset is a synthesized constant (never stored) so it can't be overridden.
3. *Event "Copy info"* (`content/event-info.ts`; on by default, popup toggle `eventInfoEnabled` in `storage.local`, mirrored onto `<html data-epitools-event-info="on">` by the isolated `event-info-toggle.ts` since the MAIN world can't read storage): a button next to the × of the planning's event-details modal that copies a standardized `%%%` description block (module code, title-derived project/type, event id) plus module/project/activity links. The event record (incl. `projectInstanceId`, never shown in the DOM) is read from React props via `extractPlanningEvent` in `fiber-extract.ts`. There is no activity page on the site; `/planning?eventId=N` opens the modal directly.
4. *Evaluation sheet PDF* (off by default; popup toggle `evalSheetEnabled` in `storage.local`): a "Fiche d'évaluation" button in the planning event modal opens an options modal, then downloads a French grading sheet (activity, module, location (`event.rooms`), day, time; per student photo, name/email, one score box per configured notation field — default Participation /5 and Acquisition /5 — and an optional blank Commentaire column; sorted by email). Regular events get one header button; events with `activitySlotsEnabled` get one button per appointment time slot plus a header button "Fiche (tous les créneaux)" for the whole event: students carry `slotStart`/`slotEnd`, are sorted by slot then email, and the PDF adds a narrow leftmost column with the slot time written vertically (`rotate90` text in `pdf.ts`), merged over that slot's rows. In landscape a slot that would be split but fits on one page (≤ 4 students) starts on the next page instead; larger slots (and portrait) split, with the cell re-drawn on each page. Split in two worlds:
   - `eval-sheet-page.ts` (MAIN) injects buttons and reads data from the site's React Query cache (QueryClient found via fibers, `findQueryClient`): `['events','detail',id,'registrations']` and `['eventSlots','list',id]`. Photos: `GET /api/users/<login>/avatar` needs the site's bearer token (cookies get 401), and the site does **not** load student avatars in the event modal, so they're fetched through the site's own generated API client, found as a React context value on a fiber ~20 levels above the dialog (`findApiClient`: `api.unlabeled.getAvatar(login)` → 240×240 JPEG Blob, converted to a data URL in the MAIN world; fallback `getAvatarThumbnail` → 96×96 data URL or null), 6 at a time. Don't read MSAL tokens from localStorage instead. Slot cards are matched to slot groups **by content** (times in the header + student names), never by position, so a sheet can't get the wrong students.
   - It hands the data to `eval-sheet.ts` (isolated) via `window.postMessage` (with a `requestId`, also set as `data-epitools-request-id` on the button; the reply is just an ack `epitools-eval-sheet-ack` within 5 s, after which progress/errors live in the options modal). That script opens the options modal (`eval-sheet-modal.ts`: orientation, comment column, reduced header = module + date/time only, custom notation fields, presets) and mirrors the toggle onto `<html data-epitools-eval-sheet="on">` for the MAIN world, re-encodes the photo data URLs to JPEG via canvas (only `data:image/` URLs are accepted — the postMessage is forgeable), and builds the PDF. (Photos used to be presigned S3 URLs fetched via the background with an optional host permission; that path was removed when the site switched to its own avatar endpoint.)
   - PDF is produced by a tiny hand-written writer (`pdf.ts`; standard Helvetica with WinAnsiEncoding, JPEG images) — not jsPDF (innerHTML/AMO, optional dynamic imports). `pdf-fonts.ts` widths are generated from the metric-compatible URW NimbusSans fonts; don't hand-edit. Layout is in `eval-sheet-pdf.ts`; `maxFields()` there is the single source of truth for how many notation columns fit, used by the modal too. Portrait = separate photo column; landscape = compact 3-column header, photo stacked above name/email in one column, exactly 4 tall rows per page, narrow score columns so the comment column gets the space.
   - Options modal: mounted **inside the intranet's Mantine dialog** (found from the button's request id), not under `<body>` — Mantine's focus trap and react-remove-scroll would otherwise eat focus and wheel events. Escape is caught on `window` in the capture phase so it doesn't also close the event modal. Own backdrop class (`epitools-es-backdrop`), never `.epitools-modal-backdrop` (`closeSaveFilterModal` removes those). Presets (`eval-sheet-presets.ts`) follow the units model: synthesized "Défaut" (`__default__`, never stored), `evalSheetPresets` + `evalSheetSelectedPresetId` in `storage.local`, sanitized on load; plus delete (two-click confirm, no `confirm()`).

**Backend:** `requireAuth` (Bearer token vs comma-separated `ALLOWED_TOKENS`) guards `/factions` and `/assignments`; CORS/OPTIONS handled before auth; `/health` is open.

## Conventions and hard-won gotchas

The intranet's DOM is not under our control, so most non-obvious code exists to survive its quirks. Check these before changing behavior:

- **Detect by DOM shape/content, not header text or URL.** The site is localized (French verified) — column headers, aria-labels and button labels differ. Student tables are found by an email-shaped `<p>` in *any* cell (not the first — some views add a leading checkbox column). Where labels are unavoidable, both languages are listed (`REGISTRATION_DATE_LABELS`, `ATTENDANCE_LABELS`, `EXPORT_BUTTON_LABELS`); the units-page filter aria-labels are English-only and unverified in French. The one deliberate URL gate is `unit-filters.ts` (`/units/my`), checked inside the recurring `check()`, not once at init, because navigation is client-side.
- **Modals/tabs mount and unmount without navigation**, so both content scripts run a body `MutationObserver` with a debounced `check()`. Never re-render already-processed rows/badges on every mutation — that self-triggers an infinite loop that hangs the tab. Only re-render on genuine data change.
- **Debounce with `setTimeout`, never `requestAnimationFrame`** (and poll with `setTimeout`): rAF is throttled to a crawl in unfocused tabs and silently stalled reapply flows for 10+ seconds.
- **No `innerHTML` with dynamic content** (AMO addons-linter rejects it); build DOM with `createElement`/`createElementNS`. Don't reuse the `.epitools-menu` class for unrelated popups — `closeAnyOpenMenu()` removes every element with it.
- **Driving the site's own React/Mantine inputs from the content script** (units page): set text via the native `HTMLInputElement.prototype.value` setter + a bubbling `input` event. Mantine comboboxes (Semester/Campus) only open on a *value change* (not focus/click); resolve the listbox via the input's own `aria-controls` (a global `[role=listbox]` query can hit the wrong one); select an option with the full `pointerdown/mousedown/pointerup/mouseup/click` sequence (`.click()` alone does not commit). All of this is flaky on fresh page load, hence: wait for the Name filter input to exist plus a short settle delay before touching anything, retry the open step, and verify-and-retry the whole apply (`applyColumnsReliably`). Compare against current input values first so a no-op apply touches nothing (`''` is a real "clear" target; `null` means "not managed"). Serialize applies through `applyInFlight` so overlapping runs can't fight.
- **Known unfixable site bug:** clicking the native clear (×) on Semester/Campus (by a user or by us) desyncs MRT's internal filter state ("No results found" or the old filter sticking) until a full page reload. The extension shows a warning toast rather than trying to work around it — don't spend time hunting for a workaround; several were tried.
- **Reload/context gotcha:** an "Extension context invalidated" error in a stale tab just means the tab wasn't refreshed after an extension reload; `initFeatureToggle` swallows it.
- **Debugging content scripts:** isolated-world `console.log` is not visible to the Chrome automation tooling, and the page's `window`/`chrome.*` aren't reachable from injected page JS. Writing diagnostics into a `data-*` attribute on `document.body` (readable from the page world) worked; remove it afterwards. Also don't trust "navigate to the same site" in a reused tab as a reload — open a fresh tab to test a new build.
