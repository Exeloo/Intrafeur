# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Intrafeur": a Chrome + Firefox (Manifest V3) extension that augments the Epitech pedagogy intranet (`my.epitech.eu`, a React + Mantine + Mantine React Table SPA), plus a small backend it talks to. Two independent apps in one repo:

- `extension/` — TypeScript, bundled with esbuild. No test suite, no linter; `typecheck` is the only check.
- `backend/` — Express + better-sqlite3, shared by all staff; stores factions and student→faction assignments. Deployed via the root `docker-compose.yml` (Dokploy builds `./backend`; token/port come from root `.env`, see `.env.example`).

## Commands

Extension (run from `extension/`):
- `npm run typecheck` — `tsc --noEmit` (this is the verification step; there are no tests)
- `./build.sh` — full build + packaging. Produces `dist/chrome/`, `dist/firefox/`, `dist/intrafeur-chrome.zip`, `dist/intrafeur-firefox.xpi`. (`node build.js` alone builds the two dirs and an intermediate `.xpi`; `build.sh` adds the chrome zip and renames the xpi. There is no `zip` CLI on the dev machine, so packaging uses Python's `zipfile`.)
- `npm run watch` + `npm run dev:firefox` / `npm run dev:chrome` — rebuild on save and auto-reload the extension via `web-ext run` (persistent profile in `extension/.dev-profile/`, so the intranet SSO login sticks). The intranet tab still needs F5 after a reload.
- Version lives only in `package.json`; `build.js` writes it into both output manifests.
- `npm run release:firefox` (`scripts/release-firefox.sh`, settings read from the repo-root `.env`, see `.env.example`) — Firefox self-hosted updates: builds with `FIREFOX_UPDATE_URL` baked into `gecko.update_url` (must be there before signing), signs unlisted on AMO via `web-ext sign`, then PUTs the signed xpi to the backend's `/extension/releases/<version>` (`RELEASE_TOKEN`, separate from `ALLOWED_TOKENS`). The backend stores releases in `DATA_DIR/releases` and serves the public `/extension/updates.json` (links built from `PUBLIC_URL`). Chrome gets no `update_url`; it updates through the Web Store (unlisted).
- `optional_host_permissions: <all_urls>` is used: it's what `options.ts` requests for the user-configured backend origin. Don't remove it.
- Load `dist/chrome` unpacked in `chrome://extensions`. **After every rebuild the extension must be reloaded there AND the intranet tab must be genuinely reloaded (F5)** — content scripts are not re-injected into already-open tabs, and in-app SPA route changes are not reloads.

Backend (from `backend/`): `npm run build` (tsc), `npm start`, `npm run typecheck`. Locally it only really runs in Docker (`docker compose up --build` from the repo root) — `better-sqlite3` fails to compile on the host Node version; use `npm install --ignore-scripts` if you only need typechecking.

## Architecture

**Extension entry points** (each is one esbuild IIFE bundle; `webextension-polyfill` is inlined): `background.ts`, `content/attendance.ts`, `content/unit-filters.ts`, `content/eval-sheet.ts`, `content/event-info.ts`, `content/event-info-toggle.ts`, `content/eval-sheet-page.ts`, `content/intrastek.ts`, `content/intrastek-page.ts`, `content/absence-status.ts`, `options/options.ts`, `popup/popup.ts`. Two manifests (`manifest.chrome.json` service worker vs `manifest.firefox.json` background scripts + gecko settings) — keep them in sync. All content scripts are listed on the same broad `https://my.epitech.eu/*` match and self-gate at runtime. `event-info.ts`, `eval-sheet-page.ts`, `intrastek-page.ts` and `absence-status.ts` are a separate `content_scripts` entry with `"world": "MAIN"` (Chrome 111+ / Firefox 128+): they must read React fiber data, which isolated-world scripts can't see, so they can't use `browser.*` or import the polyfill.

**Six features:**
1. *Factions* (`content/attendance.ts` + `dom-inject.ts` + `fiber-extract.ts`): injects a Faction column/badges into every student table and student card list on the site, with sort/filter and a CSV export that hijacks the native export button. Faction data is shared (backend); the content script never calls the API directly — it messages `background.ts`, which owns fetch/auth (`apiFetch`). Connection settings are in `storage.sync`; the per-browser "factions enabled" toggle is in `storage.local` (popup).
2. *Unit filter presets* (`content/unit-filters.ts`, `unit-filters-dom.ts`, `modal.ts`; on by default, popup toggle `unitFiltersEnabled` in `storage.local` — disabling removes the toolbar but leaves the table's current filter values alone): only on `/units/my`, only the "Current units" table's column-filter row. Purely local (`storage.local`), no backend. Preset selector + Save/Reset buttons injected into that table's toolbar; the built-in "Default" preset is a synthesized constant (never stored) so it can't be overridden.
3. *Event "Copy info"* (`content/event-info.ts`; on by default, popup toggle `eventInfoEnabled` in `storage.local`, mirrored onto `<html data-epitools-event-info="on">` by the isolated `event-info-toggle.ts` since the MAIN world can't read storage): a button next to the × of the planning's event-details modal that copies a standardized `%%%` description block (module code, title-derived project/type, event id) plus module/project/activity links. The event record (incl. `projectInstanceId`, never shown in the DOM) is read from React props via `extractPlanningEvent` in `fiber-extract.ts`. There is no activity page on the site; `/planning?eventId=N` opens the modal directly.
4. *Evaluation sheet PDF* (off by default; popup toggle `evalSheetEnabled` in `storage.local`): a "Fiche d'évaluation" button in the planning event modal opens an options modal, then downloads a French grading sheet (activity, module, location (`event.rooms`), day, time; per student photo, name/email, one score box per configured notation field — default Participation /5 and Acquisition /5 — and an optional blank Commentaire column; sorted by email). Regular events get one header button; events with `activitySlotsEnabled` get one button per appointment time slot plus a header button "Fiche (tous les créneaux)" for the whole event: students carry `slotStart`/`slotEnd`, are sorted by slot then email, and the PDF adds a narrow leftmost column with the slot time written vertically (`rotate90` text in `pdf.ts`), merged over that slot's rows. In landscape a slot that would be split but fits on one page (≤ 4 students) starts on the next page instead; larger slots (and portrait) split, with the cell re-drawn on each page. Split in two worlds:
   - `eval-sheet-page.ts` (MAIN) injects buttons and reads data from the site's React Query cache (QueryClient found via fibers, `findQueryClient`): `['events','detail',id,'registrations']` and `['eventSlots','list',id]`. Photos: `GET /api/users/<login>/avatar` needs the site's bearer token (cookies get 401), and the site does **not** load student avatars in the event modal, so they're fetched through the site's own generated API client, found as a React context value on a fiber ~20 levels above the dialog (`findApiClient`: `api.unlabeled.getAvatar(login)` → 240×240 JPEG Blob, converted to a data URL in the MAIN world; fallback `getAvatarThumbnail` → 96×96 data URL or null), 6 at a time. Don't read MSAL tokens from localStorage instead. Slot cards are matched to slot groups **by content** (times in the header + student names), never by position, so a sheet can't get the wrong students.
   - It hands the data to `eval-sheet.ts` (isolated) via `window.postMessage` (with a `requestId`, also set as `data-epitools-request-id` on the button; the reply is just an ack `epitools-eval-sheet-ack` within 5 s, after which progress/errors live in the options modal). That script opens the options modal (`eval-sheet-modal.ts`: orientation, comment column, reduced header = module + date/time only, custom notation fields, presets) and mirrors the toggle onto `<html data-epitools-eval-sheet="on">` for the MAIN world, re-encodes the photo data URLs to JPEG via canvas (only `data:image/` URLs are accepted — the postMessage is forgeable), and builds the PDF. (Photos used to be presigned S3 URLs fetched via the background with an optional host permission; that path was removed when the site switched to its own avatar endpoint.)
   - PDF is produced by a tiny hand-written writer (`pdf.ts`; standard Helvetica with WinAnsiEncoding, JPEG images) — not jsPDF (innerHTML/AMO, optional dynamic imports). `pdf-fonts.ts` widths are generated from the metric-compatible URW NimbusSans fonts; don't hand-edit. Layout is in `eval-sheet-pdf.ts`; `maxFields()` there is the single source of truth for how many notation columns fit, used by the modal too. Portrait = separate photo column; landscape = compact 3-column header, photo stacked above name/email in one column, exactly 4 tall rows per page, narrow score columns so the comment column gets the space.
   - Options modal: mounted **inside the intranet's Mantine dialog** (found from the button's request id), not under `<body>` — Mantine's focus trap and react-remove-scroll would otherwise eat focus and wheel events. Escape is caught on `window` in the capture phase so it doesn't also close the event modal. Own backdrop class (`epitools-es-backdrop`), never `.epitools-modal-backdrop` (`closeSaveFilterModal` removes those). Presets (`eval-sheet-presets.ts`) follow the units model: synthesized "Défaut" (`__default__`, never stored), `evalSheetPresets` + `evalSheetSelectedPresetId` in `storage.local`, sanitized on load; plus delete (two-click confirm, no `confirm()`).

5. *Intrastek* (AER staffing of intranet events in the Intrastek app, `https://intrastek.epistone.fr`; on as soon as an Intrastek key is saved in the options, **no popup toggle** by design, the popup only says so). Files: `content/intrastek-page.ts` (MAIN), `content/intrastek.ts` (isolated entry: gate, modal button, mode button, block colours, legend, right-click), `content/intrastek-ui.ts` (popup, `.epitools-menu`, "AERs needed" mini-prompt, toast), `content/intrastek-client.ts` (messaging, status cache, helpers), `content/intrastek.css`; `intrastekFetch` + `intrastek*` handlers in `background.ts`; Intrastek section of the options page.
   - **Storage (all `storage.local`, never sync: the key is personal):** `intrastekApiUrl` (default `https://api-intrastek.epistone.fr`), `intrastekApiKey` (`ik_…`, teachers and admins only: self-issued on their Intrastek profile page, or issued by an admin; the options page says where), `intrastekDefaultGroupId` (target group of the planning actions; else the user's own group, else the first allowed one), `intrastekModeEnabled`. Options: Save requests the optional host permission for the API origin (first `await` of the click, like the faction backend) and an empty key removes it (feature off); Test connection requests the permission too, then calls `/extension/me` with the *typed* values (`intrastekMe` accepts an `{apiUrl, apiKey}` override) without saving, showing name, admin/proposer role, scopes, and filling the default-group select (`me.groups`, preselecting the saved id or `me.defaultGroupId`).
   - **Two worlds, the key never reaches the page:** the isolated `intrastek.ts` mirrors "key present" onto `<html data-epitools-intrastek="on">` (not "mode on": the modal button needs tags with the mode off). While it's set, `intrastek-page.ts` tags every `.scheduler-event` and the event modal (`section[role=dialog]`, found like `event-info.ts`) with `data-epitools-event-id` (+ `-title`, `-start`, `-end` for display), re-reading the fiber on every check (blocks may be reused across navigation) and writing only changed values. The isolated side treats these as untrusted: ids must be positive integers (`parseEventId`), the rest is only rendered via `textContent`; the background re-validates ids before building URLs.
   - **Background:** `intrastekFetch` reads storage.local, checks `permissions.contains` for the API origin, sends `X-Api-Key` (Content-Type only with a body: Fastify rejects an empty JSON body). Handlers `intrastekMe`, `intrastekStatus` (chunks of 200 ids), `intrastekSet`, `intrastekRemove` (`force`), `intrastekApprove`, `intrastekCancel` **never throw**: they resolve `{ok:true,data}` / `{ok:false,status,message}` (an Error crossing `sendMessage` loses its status, and the UI needs 409). Messages: API `message`; 401 → "Invalid or expired Intrastek key", 403 with "disabled" → "Intrastek extension feature is disabled by an admin", 503 → "Intrastek can't reach the intranet".
   - **API contract** (source of truth: the `/extension/*` paths of the Intrastek repo's committed `apps/api/openapi.json`, regenerated by `pnpm api:types` and drift-checked in its CI; the types are mirrored in `src/types.ts`. `X-Api-Key` only, scopes `INTRANET_READ` for me/status and `INTRANET_WRITE` for the rest): `GET /extension/me` → user, `isAdmin`, scopes, `groups` (every visible group, for admins and teachers alike; hidden ones left out), `defaultGroupId` (the user's group when offered, else null: teachers usually have none); `POST /extension/events/status {eventIds}` (1..200) → one `{eventId, activities[], proposals[]}` per id (PENDING proposals only; every key holder sees every group); `PUT /extension/events/:eventId {groupId, nbUserAsk}` and `DELETE /extension/events/:eventId?groupId=&force=` → `{result: 'applied'|'proposed', state}` (admin applies: DRAFT activities, a long event split at the largest pause between its intranet slots / soft delete, 409 when assignations exist without `force` — the extension appends `&force=true` only when forcing, never `force=false`; teacher creates or updates their single PENDING proposal, INIT/UPDATE/REMOVE, on any visible group; a hidden group is a 403 for teachers, an unknown one a 404); `POST /extension/proposals/:id/approve` (admin) and `DELETE /extension/proposals/:id` (author cancels, admin rejects). The server fetches the intranet event itself; nothing the extension sends about the event is trusted, and nothing writes to my.epitech.eu.
   - **Merged events (Intrastek ROADMAP #113):** back-to-back events of one intranet activity (same Paris day, next start ≤ 15 min after the previous end) are **one** Intrastek activity on the first event (the head). `status` of a follower returns the head's activities, each with `headEventId` (≠ the asked id); a write on a follower is a **409** "This event follows event N…". `intrastek-page.ts` tags blocks and the modal with `data-epitools-event-activity` (the intranet `activityInstanceId`); pending proposals made on the head come back on its followers too (proposal `eventId` = the head); `groupView().linkedTo` = the API's `headEventId`, else such a proposal's `eventId`, else a display-only guess from the tagged blocks (`guessHead`). Follower blocks: class `epitools-ik-linked` (dotted outline), badge `🔗 👥 N` (the head's count; `🔗 ⏳` with only a proposal on the head), legend entry; the right-click menu only offers "Edit AERs needed on the first event…" (writes to the head id), the popup shows a note and no write buttons.
   - **Event modal:** an "Intrastek" button before the × (after "Copy info"/"Fiche…" when present) with a state dot over every group the key sees (green initialized, orange pending proposal, grey none, hollow unknown). It opens a popup mounted inside the Mantine dialog (same reasons and Escape capture as the eval-sheet modal; own backdrop `epitools-ik-backdrop`): title/date, group select (default = configured group), state per group (count, AERs needed, status, assigned) and pending proposal (kind, value, author, "yours"), "AERs needed" prefilled from the proposal else the activities. Admin: Apply, Remove (two-click; on 409 a "Remove anyway" with `force=true`), Approve/Reject when pending. Teacher (any non-admin key holder): Propose / Update my proposal, Propose removal, Cancel my proposal; another user's pending proposal is shown read-only and disables proposing for that group. Toast: "Applied" or "Proposal sent – waiting for admin approval".
   - **Intrastek mode:** an "Intrastek mode" toggle **deep-cloned** from the site's "Enable planning mode" button (classes/structure only; the site's button is never clicked or changed; `cloneNode` carries no React fiber/listeners and our click stops propagation), inserted just left of it in the same Mantine Group (re-placed only if a re-render moved it), marked `data-epitools-ik-mode`. Found by shape: first `button[data-with-left-section]` whose parent is a `.mantine-Group-root` next to a title, outside the calendar (`.scheduler-calendar`) and dialogs; fallback label `/planning mode|mode planning/i` (FR label unverified). Shown only when the planning calendar (`.scheduler-calendar`; FullCalendar's classes are hashed, there is no `.fc`) is on the page. When on: debounced status fetch of the tagged ids (cache: 60 s TTL, in-flight map so concurrent callers await the same request, 30 s backoff after a failure; after any write every entry goes stale and the write's own `state` is stored), block classes relative to the **target group** — `epitools-ik-initialized` (green outline + badge "👥 N", N = max `nbUserAsk` of the group's activities since a lunch-split event has two rows, "?" when ≤ 0), `epitools-ik-proposed` (orange dashed + "⏳"), `epitools-ik-none` (dimmed) — a legend under the toolbar row (starting with an **"Intrastek group" `<select>`** of `me.groups`: the group the colours, the right-click menu and the event popup target; it writes `intrastekDefaultGroupId`, the same key as the options page, so both stay in sync; disabled with fewer than 2 groups), and a right-click `.epitools-menu` (`data-epitools-ik-menu`; `contextmenu` captured on `window`, `preventDefault` only on a block in this mode): Init… / Edit AERs needed… (custom mini-prompt, never `prompt()`), Remove (two-click, 409 → toast "Remove anyway") / Propose removal, Approve / Reject, Cancel my proposal, Open details (`block.click()`, the site's left-click). Anyone with several groups (admins and teachers) gets a group select at the top of the menu and in the mini-prompt. Each block carries a signature (`data-epitools-ik-sig`: id + class + badge) so checks only touch blocks whose state changed (or whose class/badge React dropped). Turning the mode off removes classes, badges, legend and menu.
   - **Live DOM facts (week view, verified):** blocks are `div.scheduler-event[role=button]` (~52/week); `el[__reactFiber$…].return.memoizedProps.renderProps.event` is a FullCalendar EventApi whose `.id` is the intranet event id (string) and `.extendedProps` has `id`, `fullTitle`, `startDate`, `endDate`, `unitCode`, `unitName`, `rooms`, `activityName`, `projectInstanceId`, `activityInstanceId`, `registrationsCount`, `maxCapacity`… (`extractSchedulerEvent` walks a few `.return` levels rather than assuming depth 1). The header Group holds "Enable planning mode" (left-section button) plus an icon-only button. MONTH/WEEK/DAY switches and prev/next re-render the blocks. Unverified: month view block shape, the FR label.

6. *Absence attendance button* (`content/absence-status.ts` (MAIN) + `absence-status.css`; on by default, popup toggle `absenceStatusEnabled` in `storage.local`, mirrored onto `<html data-epitools-absence-status="on">` by `event-info-toggle.ts`, which mirrors both MAIN-world toggles): on a student's Absences tab (`/students/<login>#absences`, "By activities"), each absence card's static "Absent" badge is hidden by CSS (`data-epitools-absence-native`, never removed: React owns it) and followed by a hand-built copy of the planning modal's Attendance badge-button + Mantine menu (Mark present / Mark absent / Justify absence; Mantine classes, badge CSS variables and tabler icon paths captured live). A choice calls the site's own API client `api.events.setAttendance(eventId, {records:[{login, status}]})` (`POST /events/:id/attendance/set`, statuses `present`/`absent`/`justified`) — exactly what the planning cell does. Verified live: the list (`['attendanceActivities','students',login]`, `GET /events/attendance/students/:login/activities`) holds only `absent` records (justified ones are left out) with no status field; each card's wrapper fiber (prop `accentBorderSide`) is keyed `${eventId}-${startDate}` and the list component above has a `login` prop (`extractAbsenceCard`). That shape alone is not trusted: a card is only used if that query's cached records contain its `eventId` + `startDate` (`isListedAbsence`), so a lookalike card on another tab can never write to an unrelated event. The new status is kept locally per card (the list isn't invalidated, so a change can be reverted until reload); errors show "Error" on the badge for 2.5 s with the message as its title. Labels are English (the native "Absent" text is reused while unchanged); the planning menu's French labels weren't captured, so a French UI gets English menu items.

**Backend:** `requireAuth` (Bearer token vs comma-separated `ALLOWED_TOKENS`) guards `/factions` and `/assignments`; CORS/OPTIONS handled before auth; `/health` is open.

## Conventions and hard-won gotchas

The intranet's DOM is not under our control, so most non-obvious code exists to survive its quirks. Check these before changing behavior:

- **Detect by DOM shape/content, not header text or URL.** The site is localized (French verified) — column headers, aria-labels and button labels differ. Student tables are found by an email-shaped `<p>` in *any* cell (not the first — some views add a leading checkbox column). Where labels are unavoidable, both languages are listed (`REGISTRATION_DATE_LABELS`, `ATTENDANCE_LABELS`, `EXPORT_BUTTON_LABELS`); the units-page filter aria-labels are English-only and unverified in French. The one deliberate URL gate is `unit-filters.ts` (`/units/my`), checked inside the recurring `check()`, not once at init, because navigation is client-side.
- **Modals/tabs mount and unmount without navigation**, so both content scripts run a body `MutationObserver` with a debounced `check()`. Never re-render already-processed rows/badges on every mutation — that self-triggers an infinite loop that hangs the tab. Only re-render on genuine data change.
- **Debounce with `setTimeout`, never `requestAnimationFrame`** (and poll with `setTimeout`): rAF is throttled to a crawl in unfocused tabs and silently stalled reapply flows for 10+ seconds.
- **Throttle `check()`, never a restart-on-every-mutation debounce**: schedule one `setTimeout` on the first mutation and ignore the next ones until it fires (`if (timer !== undefined) return`). The site rewrites its `<style>` tags every ~100 ms on some views (planning with several semesters selected), so a `clearTimeout` + `setTimeout` debounce never fires there: no tagging, no modal buttons.
- **No `innerHTML` with dynamic content** (AMO addons-linter rejects it); build DOM with `createElement`/`createElementNS`. Don't reuse the `.epitools-menu` class for unrelated popups — `closeAnyOpenMenu()` removes every element with it.
- **Driving the site's own React/Mantine inputs from the content script** (units page): set text via the native `HTMLInputElement.prototype.value` setter + a bubbling `input` event. Mantine comboboxes (Semester/Campus) only open on a *value change* (not focus/click); resolve the listbox via the input's own `aria-controls` (a global `[role=listbox]` query can hit the wrong one); select an option with the full `pointerdown/mousedown/pointerup/mouseup/click` sequence (`.click()` alone does not commit). All of this is flaky on fresh page load, hence: wait for the Name filter input to exist plus a short settle delay before touching anything, retry the open step, and verify-and-retry the whole apply (`applyColumnsReliably`). Compare against current input values first so a no-op apply touches nothing (`''` is a real "clear" target; `null` means "not managed"). Serialize applies through `applyInFlight` so overlapping runs can't fight.
- **Known unfixable site bug:** clicking the native clear (×) on Semester/Campus (by a user or by us) desyncs MRT's internal filter state ("No results found" or the old filter sticking) until a full page reload. The extension shows a warning toast rather than trying to work around it — don't spend time hunting for a workaround; several were tried.
- **Reload/context gotcha:** an "Extension context invalidated" error in a stale tab just means the tab wasn't refreshed after an extension reload; `initFeatureToggle` swallows it.
- **Debugging content scripts:** isolated-world `console.log` is not visible to the Chrome automation tooling, and the page's `window`/`chrome.*` aren't reachable from injected page JS. Writing diagnostics into a `data-*` attribute on `document.body` (readable from the page world) worked; remove it afterwards. Also don't trust "navigate to the same site" in a reused tab as a reload — open a fresh tab to test a new build.
